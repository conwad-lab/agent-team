# Setup and walls in full (human)

`CLOUD.md` holds the rules every thread reads each turn. This file holds what only the human does, once per repo, and the full text of each wall in `CLOUD.md` § Walls, moved here unchanged in v0.8.0 so the per-turn file stays short. Every condition below binds as if it stood in `CLOUD.md`; where the two differ, the stricter one holds. Every step in § One-time setup per repo is an **Operatör** step: only the human does it. § Walls in full says what the human sets up and no agent changes; the steps it gives the Coordinator, the Judge and the Builder are those roles' own, as `CLOUD.md` says.

## One-time setup per repo

1. Codex: connect the repo, and turn on automatic code review for it (Codex settings → Code review).
2. Codex: create an environment for the repo (Codex settings → Environments) so `@codex` tasks can run; then the repo can use `builder: codex`.
3. Paste `assets/cloud/project-instructions.md` (filled in) as the project's instructions.
4. In the repo: `.team/team.md` gets `mode: cloud`, `builder: codex` once the Codex environment exists (else `builder: claude`), and a `merge:` line; `AGENTS.md` gets the cloud settings (including **Data changes**) and `## Code Review Rules` from `assets/root/AGENTS.md`.
5. Private repo with its own CI on the host Mac: install the runner per `team/RUNNER.md` § Install, then `runner: mini` in `.team/team.md` and `runs-on` as in `CLOUD.md` § Quota in every workflow. Public repos stay on `runner: github`.
6. The main ruleset (§ Walls in full below), as the human on their own admin login, never with a token in a session: fill in the required checks in `assets/cloud/main-ruleset.json` (or delete that rule, § Walls in full below) and run `gh api -X POST repos/<owner>/<repo>/rulesets --input main-ruleset.json`; or click Settings → Rules → Rulesets → New branch ruleset: name `main: PR only`, Enforcement Active, no bypass, target the default branch, then Restrict deletions, Require a pull request (0 approvals, merge method Squash), Require status checks (the always-running jobs), Block force pushes, Create. The Coordinator writes this as an Operatör row per repo and checks it afterwards with `gh api repos/<owner>/<repo>/rules/branches/<branch>`.
7. The deny list from `assets/root/.claude/settings.json` in the repo's `.claude/settings.json`, and `.claude/settings.json` on **Human-merge paths**. Where `AGENTS.md` lets board files go straight to main, that line changes to board PRs in the same PR.
8. The merge workflow (§ Walls in full below): `assets/root/.github/workflows/agent-team-merge.yml` into the repo's `.github/workflows/` (with `runs-on` as in `CLOUD.md` § Quota under `runner: mini`), and `.github/workflows/agent-team-merge.yml` on **Human-merge paths**; the repo variables `AGENT_ACCOUNT` once there is one and `AFTER_MERGE_WORKFLOWS` if a workflow must run on main after a merge (Operatör lines: repo variables need admin rights). Its install PR is the one merge the workflow cannot do yet: it needs the human's yes naming that PR (one message may name several). To let release bumps merge without a card, the same or a later install PR lists the repo's PR workflows by name under `workflow_run` and sets `- **Auto-merge:** release` in Team settings; a repo whose **Human-only paths** cover the rulebook narrows that line so the bump's files (the submodule, `.team/` board and review files, `.team/team.md`, `AGENTS.md`) are not on it. To let green rule changes merge without a card too (v0.8.19), an install PR copies the workflow again and sets `- **Auto-merge:** release, rules` and `- **Guard paths:** none` (or the repo's own extra red paths, as backticked globs); it is a red change, so it takes one card. A rulebook story's PR title carries `Rulebook story.` at its start or right after the story id (`NNN: Rulebook story. …`): the class reads it there.
9. **Stories in flight: 2** (`CLOUD.md` § Flow 3) also needs `strict_required_status_checks_policy: true` in the ruleset's required-status-checks rule, set as in step 6. Set 2 only where minutes or the runner can take double the runs.

## Walls in full

What the rules forbid is also blocked by settings, so a step that goes wrong stops at GitHub instead of reaching main.

- **Main ruleset.** Every team repo's default branch has one branch ruleset, `main: PR only`, with an empty bypass list (nobody, admins included): changes only by PR (0 approvals, squash only), the repo's required checks green, no force-push, no deletion. A ruleset, not classic protection: it works on private repos with GitHub Pro, and agents can read it (`gh api repos/<owner>/<repo>/rules/branches/<branch>`). Required checks name only jobs that run on every PR, board-only diffs included (a change classifier or gate job): a required check from a workflow skipped by a path filter stays pending and blocks every merge. A repo without such a job gets the ruleset without required checks and a Förslag row to add one. A private repo whose CI cannot run (no Actions minutes, no `runner: mini`) adds the required checks when its CI runs again, the rest at once. Setting or changing the ruleset is the human's (an Operatör row, § One-time setup per repo above); no agent changes it.
- **Board PRs.** Wherever `CLOUD.md` has the Coordinator write or push board files on main (`.team/backlog/`, `.team/plans/`, `.team/ORDER.md`, the Coordinator's lines in `.team/PAPERCUTS.md`), it does so by a board PR: a branch `board/YYYY-MM-DD-<slug>`, a PR titled `board: <what>`, one per Coordinator turn rather than one per file. The Coordinator reads the PR's head sha, lists that head's changes with renames off (`git diff --no-renames --name-only origin/<default>...<sha>`, so a rename's source and every deletion count), and when every path is a board file and the required checks pass on that head, starts a Judge thread for it (the repo, the PR number, "follow `CLOUD.md` § Judge"), and the Judge merges it with the head pinned as `CLOUD.md` § Judge 0 says. No `@codex review` (Codex's automatic review may still run; nobody waits for it), no review file, never a decision card, whatever `merge:` or **Human-merge paths** say, and a board PR does not count toward a repo's cap on open PRs. The Coordinator never merges. A board PR whose diff holds anything else is closed and the change goes through the story flow.
- **Merge workflow.** No agent session runs a merge. Claude's cloud sessions stop an agent's own `gh pr merge` unless the human's yes names that PR, which is the per-PR wait `CLOUD.md` § Human approval removed (incidents: `WHY.md` [W3]), and a repo's `permissions.allow` cannot lift that in a project with more than one repo. So the merge is GitHub's: every team repo carries `.github/workflows/agent-team-merge.yml` from `assets/root/`, and whoever `CLOUD.md` says merges (the Judge in `CLOUD.md` § Judge 0 and 5 and § Human approval 4) asks for it with a PR comment whose own line reads `agent-team-merge: <40-hex head sha>`. The workflow runs from the default branch's copy (a PR cannot change the rule it is merged under) and checks out no code. It acts only on a comment by the repo owner or the `agent-account:` login (repo variable `AGENT_ACCOUNT`), and merges (squash) only when the PR is open, not a draft and its head is the pinned sha; outside `board:` PRs, every PR also needs a Codex comment or review (of Codex's comments only a review receipt counts: a usage-limit reply, its status summary or a setup notice does not; the Judge's `Approved by <human> on a decision card, <YYYY-MM-DD>, head <sha>` line of `CLOUD.md` § Human approval 4, alone on its line and naming the pinned head, stands in for it, since that card exists because Codex could not finish a review), and in a repo with `.team/` a review file in the PR with `verdict: approve` at that sha. The ruleset still decides the rest: GitHub refuses the merge while a required check is not green. It then deletes the branch, dispatches the workflows named in the repo variable `AFTER_MERGE_WORKFLOWS` (a merge by the workflow's token starts no `push` workflow, so a workflow that must run on main gets `workflow_dispatch:` and a place in that list), and comments `Merged by agent-team-merge: head <sha>`; when it does not merge it comments why, which wakes the Judge's watch. A Judge that has seen neither comment 15 minutes after asking messages the Coordinator `NNN merge workflow did not run`; the Coordinator checks the run (no runner, no minutes) and writes the Operatör line or the runner card (`CLOUD.md` § Quota). These checks are a floor, not the Judge's review: when to ask stays `CLOUD.md` § Judge 5's rule. The workflow file is on **Human-merge paths**.
  Its job `auto` (v0.8.15, `CLOUD.md` [W6]) asks no comment. Where Team settings on the default branch list `release` on the `- **Auto-merge:**` line, it looks at a PR when its head moves or it is marked ready, when Codex comments, when a listed `workflow_run` or a non-Actions `check_suite` finishes, and squash-merges the head only when all of these hold: the PR is open, not a draft, from the same repo, against the default branch; the submodule `.claude/skills/agent-team` moves, forward (`compare` old...new is `ahead`) to a commit on the default branch of the repo `.gitmodules` names (new...that branch `ahead` or `identical`); every other path, rename sources included, is under `.team/backlog/`, `.team/plans/`, `.team/reviews/`, or is `.team/ORDER.md`, `.team/team.md`, `.team/PAPERCUTS.md` or `AGENTS.md`, and none is on the repo's **Human-only paths** (backticked globs; other text there refuses every bump); every changed `AGENTS.md` line lies inside `## Team settings` and names none of `Auto-merge`, `Human-merge paths`, `Human-only paths`, `merge:` or `Stories in flight`; `.team/team.md` changes no `human`, `merge`, `mode`, `runner`, `agent-account`, `auth` or `seats` line; a review file in the PR has `verdict: approve` at the head, and the latest review the owner or `AGENT_ACCOUNT` posted on that head (the Judge's `gh pr review` of the whole file, `CLOUD.md` § Judge 4: the commits of cloud threads carry no login that tells the Judge from the Builder) is a comment or approval whose body holds the line `verdict: approve`; Codex finished a review of the last commit outside `.team/reviews/**`, rename sources counted (a receipt naming that commit, a Codex review on it, or Codex's status summary showing it completed: never a 👍 or a timestamp, since commit dates are the pusher's to set), and no Codex receipt, review or inline comment on it carries a P0/P1 badge or an M/S number (the summary's findings flag counts the PR's open threads, not that commit), and no summary shows a review of it failed or timed out (an unreadable list of them stops the run); the latest run of every check and every status on the head is green (`success`, `skipped`, `neutral`); the head contains the default branch. A condition that is only not met yet (no review, Codex or a check still running) ends the run silently and the next event looks again; a breach (a file outside the class, a pin backwards, a finding, a red check, a stale branch) gets one comment per head, `agent-team-merge (release bump) did not merge, head <sha>: <why>`. On a merge it deletes the branch, dispatches `AFTER_MERGE_WORKFLOWS` and comments `Merged by agent-team-merge (release bump): head <sha>`. A Judge that sees neither comment 30 minutes after posting its review messages the Coordinator `NNN auto-merge did not run`, and the PR takes § Judge 5's other routes. A bump can carry anything agent-team's default branch holds: the class trusts that branch, which itself merges only through a Judge and Codex.
  **Class `rules`** (v0.8.19, `CLOUD.md` [W7]). Where that line also lists `rules` (`- **Auto-merge:** release, rules`; any other word on the line turns the job off), the job treats a PR that does not move the submodule and whose title starts with `Rulebook story.`, or has it right after the story id, as a rule change, and merges it under the same conditions as a bump (the Judge's verdict on the head, a finished clean Codex review of the last commit outside `.team/reviews/**`, every check green, the head contains the default branch) when its diff is **green**:
  - in a team repo, every path, rename sources included, is under `.team/backlog/`, `.team/plans/`, `.team/reviews/`, or is `.team/ORDER.md`, `.team/team.md`, `.team/PAPERCUTS.md` or `AGENTS.md`, with the same limits on `AGENTS.md` and `.team/team.md` lines as for a bump;
  - in the rulebook's own repo (agent-team: `team/CLOUD.md` and no `.team/team.md` on the default branch), every path is under `team/`, `bin/` or `tests/`, or is `assets/cloud/project-instructions.md`, `README.md`, `VERSION`, a `CHANGELOG`, `AGENTS.md` or `assets/root/AGENTS.md` (both only inside `## Team settings`, outside the guard keys). That repo has no review file: the verdict is the latest review the owner or `AGENT_ACCOUNT` posted on the head, a comment or approval whose body holds the line `verdict: approve`, and the Judge's comment `Judge review posted, head <sha>` wakes the job (it asks for nothing: the job reads the same facts whatever woke it).
  **Red**, hardcoded in the workflow, and never merged by this class: anything under `.github/` or `.claude/` at any depth (the merge workflow, `settings.json`), `REVIEW.md`, `.gitmodules`, the submodule, `assets/cloud/main-ruleset.json`, and every path outside the green lists; in any `AGENTS.md`, a changed line that names `Auto-merge`, `Guard paths`, `Human-merge paths`, `Human-only paths`, `merge:` or `Stories in flight`, a heading, or lies outside `## Team settings`; in `team/CLOUD.md`, a changed line inside `## Human approval`, `## Walls`, `## Data changes`, `## Rulebook changes` or step 5 of `## Judge`, or carrying `[J7]`–`[J10]` wherever it stands; in `team/SETUP.md`, a changed line inside this section; in both files a changed heading at any depth or indent, a changed line carrying markup that can hide a section (an HTML comment, a code fence, a raw HTML block, an underlined heading), and any section or Judge step added, removed, renamed or moved (compared at the merge base and the head, from the files themselves, not GitHub's patch); the repo's **Human-only paths**; and every glob on the repo's `- **Guard paths:**` line, read from the default branch, which can add red and never remove it (text there that is neither `none` nor backticked globs refuses every rule change, and only a card replaces it; a glob is read whole, spaces included). The green lists live in the workflow, so widening them is itself a red change. A red PR gets one comment per head, `agent-team-merge (rules) did not merge, head <sha>: <the rule it hit>. A red change: the PR goes to a decision card`, and the Judge acts on `CLOUD.md` § Human approval; a finding, a red check or a stale branch gets the same comment ending as for a bump. On a merge it comments `Merged by agent-team-merge (rules, green): head <sha>`.
  **Tightening** merges on the Judge's verdict and green checks alone, without waiting for Codex, under the same title: a PR whose only file (review files aside) is the pause file, added or changed, with one line `until: YYYY-MM-DD` not earlier than the one on the default branch and a line `reason: <why>`; or a PR whose only change to `AGENTS.md` is the `Guard paths` line, keeping every glob and adding at least one. It comments `Merged by agent-team-merge (rules, tightening): head <sha>`. Removing or shortening a pause, or removing a guard glob, is red.
  **Pause.** While `.team/automerge-pause` (in agent-team: `team/automerge-pause`) on the default branch holds `until:` today (UTC) or later, or holds no readable date, the class merges nothing but a tightening and says so once per head; release bumps are not paused. A pause ends by its date, or earlier only on a card.
- **Sample and pause** (`CLOUD.md` [R13]). In the routine's first run each week, after the retro: it lists the PRs across agent-team and the team repos that got `Merged by agent-team-merge (rules, green)` since the last sample, takes all of them if fewer than three, else one at random (seed: the ISO week number), and the Coordinator starts a Judge thread per pick with only the repo, the PR number and "follow `CLOUD.md` § Judge on the merged diff; answer approve, or open a revert PR". A Must fix in that review, a revert of a green rule merge within 14 days of it, or the human's own message "pausa automerge" makes the Coordinator start a pause PR in that repo (all seven on the human's word): title `Rulebook story. Pause rule auto-merge until <date>`, the pause file with `until:` 14 days on and `reason:` naming the PR or the message; a Judge thread approves it and the workflow merges it as a tightening. Until it is on the default branch the Coordinator starts no Judge on a rule change there. The first digest of the week lists the week's green rule merges, one plain-Swedish line each: what the rule now says, with the PR link. They are to read, not to answer.
- **Decision cards** (moved here unchanged from `CLOUD.md` [H2] and [H6] in v0.8.19, binding as if it stood there). Every card about a PR (merge or runner card) is logged on the PR: `Card posted <UTC time>: <exception or rule>, recommended <option>`, then `Card answered <UTC time>: <option>` (**Vänta** too). One unanswered at the routine run counts as open. The Judge turns off an auto-merge enabled on the PR (`gh api -X DELETE repos/<owner>/<repo>/pulls/<n>/ccr/auto_merge`) before the card goes out. A card's first line is `Varför du: <the wall or the disagreement>`: the red rule the workflow named, the Codex finding the Judge ruled `not valid`, the missing Codex review, or the Human-only path.
- **Deny rules.** The repo's `.claude/settings.json` carries the deny list from `assets/root/.claude/settings.json`, merged into an existing file, never replacing it: pushes to `main`/`master`, force-pushes (`--force*`, `-f` alone or in the usual groups `-uf`, `-vf`, `-qf`, `-nf`, `-uvf`, `+<ref>`, `--mirror`), `gh pr merge --admin`, and `gh api` calls on branch protection or rulesets (agents read the rules through `rules/branches`, which the list does not match). Deny wins over allow in every settings scope, so it holds for every Claude session in the repo, the human's own included. It stops the usual form of a command, not every spelling (`git -C . push` passes it): the ruleset is the wall, the deny list the early stop. `.claude/settings.json` is on **Human-merge paths**.
- **Agent account** (optional). A GitHub machine user for the agents (GitHub's terms allow one, owned by the human), a collaborator with the **Write** role on each team repo: it can push branches, open and merge PRs the ruleset lets through, and comment, but cannot change settings or rulesets. Its token is classic (`repo`): a fine-grained token cannot reach repos where its user is a collaborator on a personal account (GitHub docs, 2026-11), so the Write role is the limit. The token lives only where an agent runs as that account (the mini's Keychain for Codex CLI), never in a repo, the rulebook or a cloud environment. Creating and inviting the account is an Operatör row; `.team/team.md` then names it in `agent-account:`. From then on what that login does on GitHub is the agents', and the human's login means the human's own act. Signing stays `— <Role> (<model>) on behalf of <human>`, a PR with an exception in `CLOUD.md` § Human approval is still approved on a decision card (not a GitHub review), and the bypass list stays empty. Cloud threads act through the Claude GitHub App on the human's login until a thread can take another identity: for them nothing changes yet.
